# 3B International — audit et paiement

8 septembre 2026

Le site actuel est accessible sur [3B International](https://3b-international.vercel.app/). La visite a couvert l’entrée, le menu, la boutique, le manga, le passeport, les cartes de fidélité, le Monde du 3B, les jeux, la musique, la communauté, le sport, l’IA et le coffre secret. Le fonctionnement de l’inscription et des réglages a été examiné dans le code, sans créer de compte ni modifier de données en ligne.

Le dépôt public identifié est [3bblackblancbeurr/3b-international-](https://github.com/3bblackblancbeurr/3b-international-), branche `main`, commit de départ `e49195ef95586119f702569480d5ae7454c30d25` du 25 mai 2026. Son menu et ses textes correspondent aux écrans visités. L’association exacte du déploiement Vercel à ce commit n’a pas pu être contrôlée dans Vercel.

**Résultat : l’intégration boutique et paiement est préparée dans une copie du projet, avec une présentation d’attente sans vêtements. Elle n’est pas encore mise en ligne ni configurée avec les clés du compte Stripe marchand.**

À la demande d’une installation sans vêtements, la préparation inclut désormais un catalogue géré depuis Stripe : une fois les services configurés, la publication des produits s’y effectue sans modifier le code ni redéployer. La boutique vide affiche « Collection en préparation » et ne permet aucun paiement. Le plugin Stripe a été connecté pendant la session ; cette connexion ne configure pas automatiquement les clés privées du serveur Vercel.

## Ce que contient l’intégration de paiement

Le parcours préparé est : choix du vêtement et de sa variante, panier, frais de livraison, page Stripe, puis retour dans la boutique avec vérification du paiement. Les coordonnées bancaires sont saisies chez Stripe. Les commandes payées sont enregistrées dans Supabase par une confirmation serveur, même si le client ferme sa page.

Le code inclut des contrôles sur les prix autorisés, les quantités, l’origine de la demande, les doubles soumissions et la signature des événements Stripe. Le panier est conservé après un retour volontaire. Une fausse URL de succès ne permet ni d’annoncer un paiement confirmé ni de lire les coordonnées d’un client. Les modalités de Checkout sont documentées par [Stripe](https://docs.stripe.com/checkout/quickstart).

Les données du passeport, son inscription, la page d’entrée et le manga restent inchangés dans cette proposition. La feuille principale `App.css` est conservée ; les styles de la boutique sont isolés dans `src/shop/shop.css`.

## Vérifications et limites

- 24 tests automatisés réussis sur les contrôles du paiement, les confirmations, les doublons, les signatures, la restauration du panier et le catalogue géré dans Stripe. Les nouveaux tests couvrent l’ajout sans redéploiement, le masquage d’un produit, le changement de prix par défaut et la pagination. Stripe et Supabase sont simulés dans ces tests ; aucune transaction marchande n’a été effectuée.
- La compilation de production Vite réussit. Le fichier de dépendances verrouillé conserve les versions existantes ; seul Stripe est ajouté.
- Un contrôle HTTP du serveur local confirme que le catalogue reste vide et le paiement désactivé en l’absence de configuration.
- La navigation du site actuel a été inspectée. L’aperçu de la nouvelle interface n’a pas pu être atteint dans le navigateur de test : son rendu sur ordinateur et téléphone reste à valider.
- Le paiement n’a pas encore été testé avec les clés du véritable compte Stripe, une véritable livraison ou la base Supabase distante.
- Il reste à gérer le stock global, les expéditions, les retours, les remboursements, les reçus et le rattachement des commandes à de vrais membres. Le code livré décrit explicitement ces limites ; il ne remplace pas ces opérations commerciales.
