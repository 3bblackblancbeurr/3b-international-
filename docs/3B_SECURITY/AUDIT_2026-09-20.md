# 3B Fortress Audit Snapshot — 2026-09-20

This snapshot separates verified facts, durable security controls and remaining platform gaps.

## Verified repository and migration integrity

- Repository is public.
- No GitHub repository rulesets are currently returned by the available API.
- Legacy branch-protection details remain unavailable to the installed integration because it lacks repository administration permission.
- Real environment files are ignored; the public `.env.example` contains empty secret placeholders.
- Applied Supabase migration history is now locked by SHA-256 integrity CI.
- The applied migration manifest contains 105 migrations and was rebuilt from `supabase_migrations.schema_migrations`, not hand-rewritten history.
- Applied migration SQL is treated as immutable. Tests must validate current security contracts without editing historical migration contents.
- Economy documentation is aligned with `economy_version=2026.2`, `xp_curve_version=global-150-v2`, level 150 = 450,992 XP.

## Verified production database state

- Supabase public tables inspected by advisors have RLS enabled.
- A table with RLS and no policy is deny-by-default; many such tables are intentionally server-only and this lint is not itself proof of exposure.
- `token_enabled=false`.
- `token_blockchain_enabled=false`.
- `token_trading_enabled=false`.
- `threeb_crypto_release_gate` approvals are all false, including testnet and mainnet authorization.
- `threeb_token_ledger` is non-authoritative staging state with anon/authenticated table access revoked.
- Token ledger writes are fail-closed unless both token and blockchain flags are enabled.
- Token reward rules and token season budgets are separately blocked by release-gate checks.
- `threeb_wallet_ledger` has unique `(user_id,event_key,event_id)`.
- Permanent item minting is idempotent per `(owner_id, origin_ref)` with a database unique index, transaction lock and replay-safe `market_mint_item` behavior.
- Economy account XP matches member profile XP in the live audit sample.
- No negative XP or Coins were observed in the live audit sample.
- No duplicate ledger event triples or duplicate transaction idempotency keys were observed.
- Reward outbox had no pending, processing or failed rows in the live audit sample.
- One `legacy` economy-version ledger row is intentionally historical evidence and is not rewritten to a newer version.

## Verified World / Passport / Ville boundaries

- Passport identity is sourced from the connected account profile, not a static personal fixture.
- Existing Ville 3B access is preserved even if the newer Souvenir unlock path would otherwise be locked.
- A new Ville 3B requires at least one validated Souvenir in the Monde du 3B.
- Ville origin country is sourced from the member profile.
- The live audit found no World save with an invalid region, malformed visited list, malformed beacon list or invalid beacon identifier.
- The live Ville audit found eight districts for the existing city and exactly its origin district unlocked.
- No live building placement existed at the time of this audit, so placement persistence is implemented and tested in code but not yet evidenced by production data.

## Runtime hardening already applied

1. Removed anon privileges on `threeb_economy_flags`.
2. Reduced authenticated privileges on `threeb_economy_flags` to SELECT.
3. Set empty `search_path` on reviewed privileged economy functions.
4. Aligned the economy XP database invariant with the authoritative server range.
5. Enabled gateway JWT verification on `world-engine` while preserving internal session validation.
6. Added rate limiting to public telemetry RPCs using an IP-derived SHA-256 pseudonymous key; raw IP addresses are not stored by the limiter.
7. Quarantined the SQL 3BC staging ledger behind a fail-closed trigger.
8. Added database-enforced crypto release gates for testnet, blockchain execution and trading/mainnet stages.
9. Made future `postgres`-owned public tables, sequences and functions private to clients by default.
10. Hardened permanent item minting against concurrent duplicate World→Ville grants using owner/origin idempotence and a partial unique index.

## Reviewed SECURITY DEFINER RPCs

Supabase advisors still report some intentionally exposed SECURITY DEFINER functions. They were reviewed rather than blindly changed:

- `app_install_ping` and `app_presence_ping`: intentional telemetry entrypoints, bounded by rate limiting and empty `search_path`.
- `nexus_remove_building` and `nexus_upgrade_building`: require `auth.uid()`, ownership, revision and idempotency controls.
- `world_party_command`: requires authenticated user, valid session, bounded actions, rate limits and transaction/advisory locks.
- `threeb_rarity_supply_status`: read-only aggregate status.

These lints remain review signals; changing the functions only to silence the advisor could break intentional application behavior.

## Fortress branch controls

- Third-party GitHub Action references used by audited workflows are pinned to immutable commit SHAs on the Fortress branch.
- Dependabot configuration exists for GitHub Actions and npm.
- The legacy Passport fixture is anonymized and explicitly non-authoritative.
- Security-boundary regression tests exist.
- Fuzz/model-check security tests exist.
- Fortress CI includes a full Git-history high-confidence secret-pattern scan, production build and high/critical production dependency audit.
- CI must be green on the current PR head before merge. Historical green results do not authorize a later head.

## Open platform gaps

### Supabase Auth
Leaked-password protection remains disabled. This is a platform Auth setting and must be enabled in Supabase dashboard when the plan supports it, then security advisors must be rerun.

### PostgreSQL `supabase_admin` defaults
`postgres` default privileges are hardened, but legacy `supabase_admin` default ACLs still grant broad defaults to anon/authenticated.
The available database connection runs as `postgres` and is not a member of `supabase_admin`, so it cannot alter those owner-level defaults.
Every application migration must therefore continue explicit REVOKE/GRANT review until an owner-capable platform action fixes them.

### GitHub repository protections
No repository ruleset is currently present. The installed integration cannot create branch protection/rulesets because it lacks administration permission.
A repository administrator should require pull requests, disallow force-push/deletion on main and require stable Fortress/World/Metropolis/Economy checks.

### Independent assurance
Still not completed:
- independent penetration test;
- independent cryptographic audit;
- red-team approval;
- Vault recovery drill using non-production material;
- MiCA/AMF legal approval;
- formal proof of a future protocol.

## 3BC boundary

There is still **no real 3BC blockchain, mainnet, production wallet key system or production Vault**.

Wallet/Vault documents are architecture only.
Any future testnet must be zero-value, faucet-only and cryptographically separated from production.
No testnet success can authorize mainnet or real value by itself.
The SQL token ledger is explicitly non-authoritative and must never be presented as the future cryptocurrency ledger.
