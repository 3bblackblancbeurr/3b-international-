This snapshot separates verified facts from open work.

## Open security findings
- Supabase compromised-password protection is disabled.
- app_install_ping/app_presence_ping intentionally expose SECURITY DEFINER telemetry RPCs and need stronger abuse/rate-limit design.
- Existing workflows use mutable action tags; security-critical CI should pin immutable SHAs.
- Some existing workflows request contents:write; each needs necessity review.
- Existing Edge Functions using legacy anon/service-role environment names should migrate toward current publishable/secret key handling without an unsafe production rotation.
- member-hub mixes public registration/recovery with authenticated operations, preventing a simple gateway-JWT switch; splitting public/private entrypoints should be evaluated.
- secret3b-claim manually authenticates users while gateway verify_jwt remains false; gateway hardening requires confirming every production client call first.

## Additional verified hardening — same-day follow-up

- Public telemetry RPCs `app_install_ping` and `app_presence_ping` remain intentionally callable, but are now rate-limited with an IP-derived SHA-256 pseudonymous key; raw IP addresses are not persisted by the limiter.

- `threeb_level_curve` was corrected to authenticated SELECT-only after a concurrent migration inherited legacy broad default grants.
- `nexus_purchase_and_place_building` was re-hardened to an empty search_path after a concurrent migration replaced the function.
- A dynamic RLS isolation check with an authenticated role confirmed that economy accounts, wallet ledger and inventory did not expose rows owned by another user.

### Open high-priority platform gap
The project has legacy PostgreSQL default ACLs that automatically grant broad privileges on newly created public-schema tables, sequences and functions to `anon` and `authenticated`. An attempt to change those owner-level defaults through the available connector was rejected with `permission denied to change default privileges`.

Until an owner-capable database operation changes those defaults, every new migration MUST explicitly revoke client privileges before it is considered safe.
